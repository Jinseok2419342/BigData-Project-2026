# 약물 리뷰 기반 부작용 위험 탐지 보고서

**과목**: 빅데이터 분석 프로그래밍  
**주제**: UCI ML Drug Review dataset 기반 심각한 부작용(ADE) 위험군 탐지  
**서비스 형태**: Streamlit 종합 관제 대시보드

---

## 1. 문제 정의

환자들이 작성한 실제 약물 복용 리뷰와 평점 데이터를 이용해, 알려지지 않은 약물 부작용 가능성을 조기에 탐지하고자 한다. 사용자는 약물명과 증상 텍스트를 입력하고, 서비스는 과거 리뷰 통계와 머신러닝 예측 결과를 바탕으로 "심각한 부작용 위험군" 여부와 위험도 점수를 보여준다.

## 2. 데이터

- 데이터명: UCI ML Drug Review dataset
- 출처: Kaggle `jessicali9530/kuc-hackathon-winter-2018`
- 형식: CSV
- 주요 컬럼: `drugName`, `condition`, `review`, `rating`, `date`, `usefulCount`
- 규모: 약 161,290행, 7열
- 라이선스/주의: 연구 목적, 상업적 이용 및 원본 데이터 재배포 제한 확인 필요

앱은 `data/` 폴더의 로컬 CSV를 우선 사용하고, 없으면 KaggleHub를 시도한다. 둘 다 실패하면 발표 시연이 막히지 않도록 데모 샘플을 사용한다.

## 3. Target 정의

원본 데이터에는 공식적인 "심각한 ADE" 라벨이 없으므로 약한 라벨링(weak labeling)을 사용했다.

위험군(1)은 다음 중 하나를 만족하는 리뷰로 정의했다.

- `chest pain`, `breathing`, `seizure`, `suicidal`, `hospital`, `swelling` 등 심각 증상 키워드 포함
- 평점이 3점 이하이고, `nausea`, `vomiting`, `dizzy`, `rash`, `panic` 등 증상 키워드 포함

그 외는 일반 리뷰/안전군(0)으로 정의했다. 이 방식은 수업용 모델을 만들기 위한 프록시 라벨이며, 실제 의학적 진단 라벨은 아니다.

## 4. EDA 발견

앱의 EDA 페이지에서 다음을 확인한다.

- 약물별 리뷰 수가 크게 다르므로, 약물별 최소 리뷰 수 필터가 필요하다.
- 위험군 후보는 낮은 평점 구간에 많이 분포한다.
- 리뷰 길이와 심각 증상 키워드 수는 위험군 분류에 유용한 신호가 된다.
- 약물별 평점 분포에서 IQR 기준 낮은 이상치를 확인하면, 같은 약물 안에서 유난히 나쁜 반응을 빠르게 찾을 수 있다.

## 5. 특성 엔지니어링

모델에는 다음 특성을 사용했다.

- 텍스트 특성: `review`의 TF-IDF 벡터
- 숫자 특성: 평점, usefulCount, 리뷰 길이, 단어 수, 느낌표 수, 대문자 비율
- 키워드 특성: 심각 증상 키워드 수, 일반 증상 키워드 수, 긍정 키워드 수
- 통계 특성: 약물별 리뷰 수, 약물별 평균 평점, IQR 낮은 이상치 여부

## 6. 모델

모델은 scikit-learn의 `RandomForestClassifier`를 사용했다.

- 입력: 리뷰 텍스트 + 숫자형 특성
- 출력: 심각한 부작용 위험군 확률
- 검증: train/test split 후 Accuracy, Precision, Recall, F1, ROC-AUC, Confusion Matrix 표시

서비스 페이지에서는 사용자가 약물명, 증상 텍스트, 평점을 입력하면 모델이 위험도 점수를 계산한다.

## 7. 서비스 구성

- EDA 대시보드: 데이터 요약, 결측치, 분포 그래프
- 인사이트 시각화: 약물별 위험군 비율, 평점 대비 위험군 산점도, 키워드 비교
- 모델 서비스: 입력 -> 예측 -> 결과 리포트
- 데이터 조회: 검색, 필터링, CSV 다운로드

이미지 업로드는 현재 약통 이미지 미리보기와 파일명 기반 약물 후보 매칭을 제공한다. 향후 OCR 또는 멀티모달 LLM을 연결하면 약물명 자동 인식까지 확장할 수 있다.

## 8. 결론

환자 리뷰 텍스트에는 심각 부작용을 의심할 수 있는 신호가 포함되어 있으며, 평점과 키워드 기반 특성을 결합하면 수업용 MVP 수준의 위험군 분류 서비스를 만들 수 있다. 특히 Streamlit에서 EDA와 예측 서비스를 한 화면 흐름으로 연결하면, 데이터 분석 결과가 실제 사용자 입력 기반 서비스로 이어지는 모습을 보여줄 수 있다.

## 9. 한계

- 원본 데이터에 실제 ADE 전문 라벨이 없어 약한 라벨을 사용했다.
- 리뷰는 사용자 주관이 강하고, 약물 용량/병력/병용약 정보가 부족하다.
- 모델 결과는 의료 판단이 아니라 참고용 신호다.
- 이미지 기반 약물명 인식은 아직 OCR/멀티모달 모델 연동 전 단계다.

## 10. 향후 개선

- 실제 ADE 라벨 데이터와 결합해 target 신뢰도 개선
- OCR 또는 멀티모달 LLM으로 약통 이미지에서 약물명 추출
- 약물별 표본 수가 작은 경우 신뢰구간 표시
- 위험군 예측의 Recall을 우선하는 threshold 튜닝
- Ollama 또는 API 기반 상담 챗봇 고도화
