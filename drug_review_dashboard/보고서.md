## 1. 문제 정의

환자들이 작성한 실제 약물 복용 리뷰와 평점 데이터를 이용해, 알려지지 않은 약물 부작용 가능성을 조기에 탐지하고자 한다. 사용자는 약물명과 증상 텍스트(선택적으로 약통 이미지)를 입력하고, 서비스는 과거 리뷰 통계(IQR)와 머신러닝 예측 결과를 바탕으로 **"심각한 부작용 위험군(1)"** 인지 **"일반 리뷰/안전군(0)"** 인지를 이진 분류하고 위험도 점수(%)를 보여준다.

## 2. 데이터 소개 & 규모

- 데이터명: UCI ML Drug Review dataset
- 출처: Kaggle `jessicali9530/kuc-hackathon-winter-2018`
- 형식: CSV / 주요 컬럼: `drugName`, `condition`, `review`, `rating`(1~10), `date`, `usefulCount`, ID
- 규모: train 약 161,297행 + test 약 53,766행 = **합계 215,063행 × 7열**
- 라이선스/주의: 연구 목적, 상업적 이용 및 원본 데이터 재배포 제한 확인 필요

앱은 `data/` 폴더의 로컬 CSV를 우선 사용하고, 없으면 KaggleHub를 시도한다(캐시는 프로젝트 내부 `.kagglehub_cache/`). 둘 다 실패하면 발표 시연이 막히지 않도록 데모 샘플로 자동 대체한다.

## 3. EDA 발견 (`eda_report.py` → `eda_outputs/` 그림 저장)

전체 데이터(215,063행)에 대한 EDA 결과:

1. **평점은 J자형 분포** — 10점(68,005건)과 1점(28,918건)이 양극단을 차지. 평균 6.99, 중앙값 8. 즉 만족/불만이 또렷이 갈린다. *(그림 `01_rating_dist.png`)*
2. **usefulCount는 극단적 우편향** — 평균 28, 최대 1,291, 왜도 4.5. 소수의 "공감 많은" 리뷰가 존재한다.
3. **질환·약물 편중** — 최다 질환은 `Birth Control`(38,436건), 이어 Depression / Pain / Anxiety. 최다 약물은 피임 관련(Levonorgestrel, Etonogestrel 등). 약물 3,671종으로 약물별 리뷰 수 편차가 커 **약물별 최소 리뷰 수 필터가 필요**하다.
4. **데이터 품질 이슈** — `condition` 컬럼 1,171행에 `</span> users found this comment helpful` 같은 **HTML 잔여물**이 섞여 있다. `review`의 `&quot;`, `&#039;` 등 HTML 엔티티도 전처리에서 복원했다.
5. **위험군(약한 라벨) 비율 18.6%** (위험 40,042 / 안전 175,021). 위험군의 평점 중앙값은 2점, 안전군은 9점으로 뚜렷이 분리된다. *(그림 `03`, `05`)*
6. **상관관계로 누수(leakage) 발견** — `risk_label`과의 상관: severe_keyword_count 0.64, symptom_keyword_count 0.34, rating −0.45. 이는 라벨이 이 신호들로 정의되었기 때문이며, **4·6장에서 다루는 핵심 교훈**으로 이어진다. *(그림 `04_corr_heatmap.png`)*

## 4. Target 정의와 ⚠️ 데이터 누수(leakage) 처리 — 핵심 교훈

원본 데이터에는 공식 "심각한 ADE" 라벨이 없으므로 **약한 라벨링(weak labeling)** 으로 프록시 target을 투명하게 정의했다.

```
위험군(1) = (심각 키워드 포함)  OR  (평점 ≤ 3  AND  증상 키워드 포함)
            └ clause A (9.6%)        └ clause B (11.3%)   → 합집합 18.6%
```

**문제점(누수):** 라벨을 *정의하는* 데 쓰인 `severe_keyword_count`, `symptom_keyword_count`, `low_rating_flag`를 그대로 모델 특성으로 넣으면, 모델은 라벨 생성 규칙을 그대로 복원할 수 있다. 실제로 이 구성에서는 **Accuracy 99.6%, F1 0.989, ROC-AUC 1.000** 이라는 비현실적 점수가 나왔다 — 예측력이 아니라 규칙 암기다.

**처리:** 라벨을 정의하는 위 3개 컬럼을 학습 특성에서 **제외**(`LABEL_DEFINING_FEATURES`)하고, 모델은 **리뷰 원문 TF-IDF + 비누수 숫자 특성**만으로 학습하도록 분리(`MODEL_FEATURES`)했다. `rating`은 사용자 제공 신호이며 단독으로는 라벨을 복원할 수 없어 유지했다.

## 5. 특성 엔지니어링

`src/features.py`에서 13개 특성을 생성한다.

- **텍스트**: `review`의 TF-IDF(1~2gram, max 1,500, 영어 불용어 제거, min_df=2)
- **언어 신호**: 리뷰 길이, 단어 수, 느낌표 수, 대문자 비율, 긍정 키워드 수
- **행동/통계**: usefulCount, 약물별 리뷰 수, 약물별 평균 평점
- **IQR 이상치**: 약물별 평점의 Q1−1.5·IQR 기준 낮은 이상치 플래그(표본 5건 미만 약물은 전체 분포로 보정)
- **라벨 정의용(모델 제외)**: 심각/증상 키워드 수, 낮은 평점 플래그 — EDA·데이터 조회에는 표시하되 학습에서는 제외

## 6. 모델 & 성능 (누수 제거, 정직한 평가)

배포 모델은 `RandomForestClassifier`, 비교군으로 `HistGradientBoostingClassifier`(XGBoost 계열)와 단순 규칙 베이스라인을 함께 평가했다. (40,000행 로딩 · 20,000 샘플 학습 · test 25% 기준)

| 모델 | Accuracy | Precision | Recall | F1 | ROC-AUC |
|------|:---:|:---:|:---:|:---:|:---:|
| **RandomForest (배포)** | 96.6% | 98.2% | 83.4% | **90.2%** | 0.983 |
| HistGradientBoosting | 99.0% | 100% | 94.9% | 97.4% | 0.988 |
| Baseline (rating≤3 규칙) | 84.5% | 57.5% | 67.1% | 61.9% | — |

- **두 ML 모델 모두 단순 규칙(F1 0.62)을 크게 능가** → 텍스트가 실제 예측 신호를 가진다.
- 누수 제거 후 상위 특성이 `rating`, `hospital`, `er`, `swelling`, `throat`, `suicidal` 등 **의미 있는 토큰**으로 바뀌었다(혼동행렬·특성 중요도는 서비스 페이지 expander에서 확인).
- 배포 모델로 RF를 택한 이유: 빠른 단건 추론, `feature_importances_` 해석 용이. HGB는 더 높은 성능을 보여 비교·향후 후보로 제시.

서비스 페이지에서 사용자가 약물명·증상 텍스트·평점을 입력하면 모델이 위험도(%)를 계산하고, IQR 이상치 여부와 함께 규칙 기반 리포트(선택적으로 Ollama 리포트)를 생성한다.

## 7. Streamlit 앱 구성

- **EDA 대시보드**: 요약 지표, 결측/스키마, 평점·리뷰 길이·위험군 분포
- **인사이트 시각화**: 약물별 위험군 비율 Top20, 평점 대비 위험군 산점도, 평점 Box/IQR, 위험군 vs 안전군 키워드 비교, 월별 추이
- **모델 서비스**: 입력 → 예측 → 위험도/IQR/리포트, **모델 비교표·혼동행렬·특성 중요도**, 약통 이미지 멀티모달 인식
- **데이터 조회**: 키워드/약물 검색, 컬럼 선택, CSV 다운로드
- **AI 상담 챗봇**: 약물 선택 → 모니터링 요약 + 부작용/주의사항 질의응답. 답변은 해당 약물 리뷰 통계·키워드에 **근거(grounding)** 하며, Ollama가 있으면 LLM이, 없으면 데이터 기반 규칙 답변이 응답(오프라인 시연 안전)

이미지 입력은 **Ollama 비전 모델(gemma3 등)로 약통 글자를 읽어 약물명을 매칭**하는 멀티모달 경로를 추가했고, 모델이 없거나 실패하면 파일명 기반 후보 매칭으로 자동 대체한다.

실행: `pip install -r requirements.txt` → `streamlit run app.py`

## 8. 결론

환자 리뷰 텍스트에는 심각 부작용을 의심할 신호가 담겨 있으며, TF-IDF + 평점/행동 특성을 결합하면 단순 규칙을 능가하는 위험군 분류 MVP를 만들 수 있다. 무엇보다 **누수를 발견·제거해 정직한 성능(F1 0.90)을 보고**한 점이 이 프로젝트의 분석적 핵심이다.

## 9. 한계

- 약한 라벨 자체가 텍스트 키워드·평점에서 파생되므로, 높은 정확도는 "키워드 규칙의 일반화"이지 **미지의 ADE를 새로 발견하는 능력은 아니다**.
- 동의어/완곡 표현 일반화는 제한적이다(예: "heart pounding out of my chest"처럼 키워드가 없는 위험 문장은 놓칠 수 있음 — 실제 테스트에서 위험도 0.39로 미감지).
- 약물 용량·병력·병용약 정보가 없고, 리뷰는 주관적이다.
- 예측은 의료 판단이 아니라 참고용 신호다.

## 10. 향후 개선

- 실제 ADE 라벨/의약품안전처 부작용 보고와 결합해 target 신뢰도 향상
- 위험군 Recall 우선 threshold 튜닝(놓침 최소화), 약물별 표본 적을 때 신뢰구간 표시
- 멀티모달 OCR 강건화(흐림/기울기 이미지), Ollama 기반 상담 챗봇 고도화
- HistGradientBoosting/XGBoost 정식 배포 및 임베딩 기반 의미 일반화
