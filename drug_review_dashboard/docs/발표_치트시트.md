## 0. 발표 당일 세팅 (앱 켜기 전 — 학교 PC, 인터넷 됨)

1. **데이터 확보** (둘 중 하나)
   - ✅ **가장 확실**: Kaggle에서 `kuc-hackathon-winter-2018.zip` 받아서 **압축 풀지 말고 그대로** `drug_review_dashboard/data/` 에 넣기 → 앱이 train+test(215k) 자동 추출.
   - 또는 그냥 `streamlit run app.py` → KaggleHub 자동 다운로드(인증 불필요). 기본설정은 train만 받지만 **데모·모델엔 충분**.
   - 둘 다 실패해도 데모샘플(480행)로 앱은 켜짐(안 멈춤). 단 지표가 작아지니 가급적 위 둘 중 하나로 진짜 데이터 확보.
2. `pip install -r requirements.txt` (최초 1회)
3. `streamlit run app.py`
4. **워밍업 필수**: EDA 페이지 1회 + **모델 서비스 페이지 1회** 열기(첫 진입 시 학습 대기 → 미리 끝내두기).
5. **모델 서비스 사이드바**: `최대 데이터 행수 = 40000`, `모델 학습 샘플 수 = 20000` 로 설정
   → 상단 지표가 보고서표와 동일(**Acc 96.6% · Recall 83.4% · F1 90.2%**), 데모 위험도 **~75%**.
6. **데모 1회 미리 실행** → 화면의 실제 위험도 %를 보고 멘트의 "약 75%"를 그 숫자로 맞추기.
7. 백업: `발표_슬라이드.pdf`(6장)와 `docs/screenshots/` 캡처를 열어두면 앱 사고 시 즉시 대체.

## 2. 데모 입력값 (슬라이드 ④ — 외워두기)

- 약물: **`Sertraline`**
- 증상: **`Severe chest pain and my heart was racing, I could not breathe.`**
- 평점: **`2`**
- 결과: 위험도 **~75%**, **심각한 부작용 위험군**, IQR 이상치 **감지**, 상담 리포트(+인터넷 시 LLM 리포트)
- 챗봇 페이지: 약물 선택 → "**흔한 부작용은?**" 버튼 한 번 → 리뷰 근거 답변

> ⚠️ 위험도 %는 당일 설정·데이터에 따라 71~78% 사이로 흔들림. **워밍업 때 본 실제 숫자로 멘트 조정.**

- **사수**: ⑤ 누수 발견→제거→정직한 성능 스토리, ④ 라이브 데모 입력→결과 1회.

## 4. 예상 코드 질문 즉답 (감점 방지 — "이 코드 뭐 하는지")

1. **약한 라벨 어떻게 만들었나?** → `features.py`의 `build_target()`: **(심각 키워드>0) OR (평점≤3 AND 증상 키워드>0)**. 정답 라벨이 없어 규칙으로 투명하게 정의.
2. **왜 96%가 "정직한" 성능인가? (가장 중요)** → 처음 99.6%는 **라벨을 정의한 컬럼**(severe/symptom 키워드 수, low_rating_flag)이 학습에 들어간 **타깃 누수**. `LABEL_DEFINING_FEATURES`로 제외하고 **`MODEL_FEATURES`+리뷰 TF-IDF**만 학습 → F1 0.90.
3. **rating은 라벨에 쓰였는데 왜 학습에 남겼나?** → clause B는 "평점≤3 **AND** 증상키워드". 키워드 수를 빼면 rating 단독으론 라벨 복원 불가 + 실사용자 입력 신호. 증거: rating만 쓰는 **베이스라인은 F1 0.62**.
4. **새로 만든 특성은?** → 원본 7컬럼 → **11개**. 약물별 IQR 저평점 이상치, 리뷰 길이·느낌표·대문자비율(감정), 긍정 키워드 수, 약물별 리뷰수·평균평점. **전부 EDA 근거**.
5. **모델/LLM은 뭘 입력받아 뭘 출력?** → ML: 약물명+증상텍스트+평점 → **위험확률%+위험군/안전군**. LLM: 예측+리뷰통계를 컨텍스트로 받아 **한국어 리포트/챗봇 답변**. LLM 없으면 규칙 답변.
6. **페이지마다 데이터 또 읽나? (캐싱)** → `data_cache.get_prepared_data` 한 곳에서 `@st.cache_data`, **5페이지가 같은 캐시 공유**. 모델은 `@st.cache_resource`(스칼라 키라 DataFrame 재해시 없음).
7. **LLM이 꺼져 있으면?** → `llm_helper.route_chat()`: **Ollama → OpenAI → None(규칙 답변)**. 각 단계가 예외를 삼켜 앱이 안 죽음. **18개 단위 테스트**로 검증.
8. **노트북과 앱이 같은 결과인가?** → 둘 다 `src/`의 `prepare_data`(load→add_features) 호출 = **단일 진실 원천**. 노트북 셀 3가 "같은 함수 쓰는지"를 코드로 증명.
9. **TF-IDF가 뭐?** → 리뷰 원문을 1~2gram·1,500차원 벡터로(영어 불용어 제거). 누수 제거 후 상위 토큰이 **hospital·er·suicidal** → 모델이 진짜 위험 어휘를 학습했다는 증거.

> 코드 위치가 헷갈리면 `docs/코드_워크스루.md`(파일·함수별 표) 한 번 훑기.

## 5. 솔직한 한계 (물어보면 — 숨기지 말 것)

라벨이 키워드·평점에서 파생됐기에 이 성능은 **"키워드 규칙의 일반화"**이지 미지의 ADE를 새로 발견하는 능력은 아님. 완곡 표현은 놓칠 수 있음(예: "heart pounding out of my chest"는 위험도 0.39로 미감지된 실측 사례). 의료 판단 아니라 **상담 연결용 참고 신호**로 포지셔닝.
