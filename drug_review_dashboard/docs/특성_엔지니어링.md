# 특성 엔지니어링 상세 — EDA 발견에서 모델 특성까지

> 이 문서는 "어떤 EDA 발견 때문에 → 어떤 특성을 → 어떻게 만들었고 → 왜 예측에 도움이 되는가"를
> 특성 하나하나 단위로 정리한다. 구현은 전부 `src/features.py`에 있으며,
> 노트북(R&D)과 Streamlit 앱(Production)이 같은 코드를 공유한다.

## 1. 원본 컬럼 vs 새로 만든 특성

원본 데이터는 **7개 컬럼**뿐이다 (표준화된 이름 기준).

| 원본 컬럼 | 의미 |
|---|---|
| `review_id` | 리뷰 고유 ID |
| `drug_name` | 약물명 |
| `condition` | 질환명 |
| `review` | 리뷰 원문 텍스트 |
| `rating` | 환자 평점 (1~10) |
| `date` | 작성일 |
| `useful_count` | "도움이 됐다" 공감 수 |

여기에 `add_features()`가 **11개의 새 수치 특성 + 약한 라벨(`risk_label`)** 을 만들고,
모델 단계(`src/modeling.py`)에서 **리뷰 원문 TF-IDF(1,500차원)** 가 추가된다.
즉 "원본 컬럼 그대로"가 아니라 가공·결합·도출한 특성이 모델 입력의 대부분이다.

## 2. 특성별 상세표 — EDA 근거 · 계산 방법 · 예측 유용성

### 2-1. 언어/감정 신호 특성 (4개) — 모두 학습에 사용

| 특성 | 만든 동기 (EDA 발견) | 계산 방법 | 왜 예측에 유용한가 |
|---|---|---|---|
| `review_length` | 리뷰 길이 분포에서 **위험군이 더 긴 구간까지 분포** (그림 02) | `review` 글자 수 | 부작용 경험은 길게 서술되는 경향 → 길이 자체가 위험 방향의 약한 신호 |
| `word_count` | 위와 동일 | 영문 단어 패턴 `[A-Za-z']+` 매칭 개수 | 글자 수보다 문장 부호·공백에 강건한 길이 신호 |
| `exclamation_count` | 위험군 리뷰에 격한 감정 표현이 많음 | `!` 개수 | 감정 강도(분노·놀람)의 직접적 지표 |
| `uppercase_ratio` | "NEVER take this" 같은 대문자 강조가 위험 리뷰에 등장 | 영문자 중 대문자 비율 | 강조·분노 표현의 정량화 |

### 2-2. 키워드 사전 특성 (3개) — 2개는 라벨 정의용(학습 제외)

| 특성 | 만든 동기 (EDA 발견) | 계산 방법 | 학습 사용 여부 |
|---|---|---|---|
| `severe_keyword_count` | 정답 라벨이 없으므로 **약한 라벨의 재료**가 필요 | 21개 심각 증상 사전(chest pain, seizure, suicidal, ER...)과 단어 경계 정규식 매칭 — **서로 다른 키워드 종류 수** | ❌ **제외** (라벨 정의 컬럼 → 누수) |
| `symptom_keyword_count` | 위와 동일 | 17개 일반 증상 사전(nausea, dizziness, rash...) 동일 방식 | ❌ **제외** (라벨 정의 컬럼 → 누수) |
| `positive_keyword_count` | 키워드 비교 차트에서 **안전군 상위 단어가 worked/helped/improved 계열**로 뚜렷 | 10개 긍정 어휘 사전 동일 방식 | ✅ 사용 (라벨 정의에 안 쓰여 비누수) — 안전군 방향의 신호 |

> 구현 포인트: 키워드 카운트는 키워드 세트당 **정규식 1개를 미리 컴파일**(`lru_cache`)해 재사용한다.
> 행×키워드만큼 `re.search`를 도는 방식 대비 5만 행 기준 약 4배 빠르다.
> 긴 구("chest pain")를 짧은 단어("pain")보다 먼저 매칭해 중복 집계를 막는다.

### 2-3. 평점 파생 특성 (2개) — 1개는 라벨 정의용(학습 제외)

| 특성 | 만든 동기 (EDA 발견) | 계산 방법 | 학습 사용 여부 |
|---|---|---|---|
| `low_rating_flag` | 평점이 **J자형 분포**(10점·1점 양극단, 그림 01) → "불만"은 1~3점에 집중 | `rating ≤ 3` 이진 플래그 | ❌ **제외** (약한 라벨의 clause B 재료) |
| `rating_iqr_low_outlier` | **약물마다 평점 분포가 제각각**(Box Plot) — 같은 2점도 약물에 따라 의미가 다름 | 약물별 `Q1 − 1.5×IQR`보다 낮으면 1. 리뷰 5건 미만 약물은 분위수가 불안정해 **전체 분포로 보정** | ✅ 사용 — "그 약물 기준으로 비정상적으로 낮은 평점"이라는 맥락화된 신호 |

### 2-4. 약물 단위 통계 특성 (2개) — 모두 학습에 사용

| 특성 | 만든 동기 (EDA 발견) | 계산 방법 | 왜 예측에 유용한가 |
|---|---|---|---|
| `drug_review_count` | **약물 3,671종, 리뷰 수 편차 극심** (Birth Control 약물에 편중, 그림·EDA 발견 3) | 약물별 리뷰 수 groupby 집계 | 통계 신뢰도의 프록시 — 리뷰가 적은 약물의 신호는 불확실 |
| `drug_avg_rating` | 약물 자체의 "평판 기준선"이 필요 | 약물별 평점 평균 | 입력 평점과 약물 평판의 괴리를 모델이 학습 가능 |

### 2-5. 원본 그대로 쓰는 수치 (2개)

| 특성 | 학습 사용 여부 | 비고 |
|---|---|---|
| `rating` | ✅ 사용 | 사용자가 직접 준 신호. **증상 키워드 수 없이는 라벨을 복원할 수 없어** 유지 (보고서 3.3절). 단순 규칙 베이스라인(rating≤3, F1 0.62)과의 비교로 "rating만으로는 부족함"을 증명 |
| `useful_count` | ✅ 사용 | EDA: 극단적 우편향(왜도 4.5) — 공감 많은 리뷰는 커뮤니티가 주목한 사례 |

### 2-6. 텍스트 특성 — 리뷰 원문 TF-IDF (모델 단계)

- **EDA 근거**: 위험군/안전군 키워드 비교 차트에서 두 군의 어휘가 뚜렷이 갈림.
- **계산**: `TfidfVectorizer(max_features=1500, ngram_range=(1,2), min_df=2, stop_words="english")`
- **유용성**: 키워드 사전에 없는 표현까지 모델이 데이터에서 스스로 학습. 누수 제거 후
  특성 중요도 상위가 `hospital`, `er`, `swelling`, `throat`, `suicidal` 등 **의미 있는 의학 토큰**으로
  나타나 모델이 "진짜 위험 어휘"를 배웠음을 보여준다.

## 3. 약한 라벨(target) 정의 — 특성이 라벨이 되는 경로

```
risk_label(위험군=1) = (severe_keyword_count > 0)                  ← clause A: 전체의 9.6%
                       OR (rating ≤ 3 AND symptom_keyword_count > 0) ← clause B: 전체의 11.3%
                                                                      합집합: 18.6%
```

- 심각 키워드는 **평점과 무관하게** 위험 (응급 신호는 평점이 높아도 위험).
- 일반 증상 키워드는 흔하므로 **낮은 평점과 결합될 때만** 위험으로 본다.
- 교수님 피드백("정답 라벨이 없으니 규칙 기반 약한 라벨로 시작하라")을 그대로 반영한 설계.

## 4. 타깃 누수 차단 — 이 프로젝트의 핵심 의사결정

| 구분 | 컬럼 | 모델 입력 |
|---|---|---|
| `LABEL_DEFINING_FEATURES` (라벨 정의 3개) | `severe_keyword_count`, `symptom_keyword_count`, `low_rating_flag` | ❌ 제외 |
| `MODEL_FEATURES` (비누수 10개) | rating, useful_count, review_length, word_count, exclamation_count, uppercase_ratio, positive_keyword_count, rating_iqr_low_outlier, drug_review_count, drug_avg_rating | ✅ 사용 |
| 텍스트 | `review` → TF-IDF 1,500차원 | ✅ 사용 |

- 라벨 정의 3개를 넣고 학습하면 **Acc 99.6% / AUC 1.000** — 모델이 라벨 생성 규칙을 암기한 것.
- 제외 후 **Acc 96.6% / F1 0.902** — 더 낮지만 "정직한" 일반화 성능.
- 판단 기준: **"이 특성이 `build_target`의 결정적 구성 요소인가?"** 그렇다면 무조건 제외.
  `rating`은 clause B의 일부지만 증상 키워드 수 없이 단독으로 라벨을 복원할 수 없고,
  실서비스에서 사용자가 직접 입력하는 진짜 신호이므로 유지했다.

## 5. 새 특성을 추가할 때의 규칙 (유지보수 가이드)

1. `add_features()`에 계산 추가 → `NUMERIC_FEATURES` 목록에 등록.
2. **이 특성이 라벨 정의에 쓰이는가?** 쓰이면 `LABEL_DEFINING_FEATURES`에도 등록(자동으로 학습 제외).
3. 노트북을 다시 실행해 앱과 출력이 동일한지 확인 (공유 모듈이므로 자동 반영).
